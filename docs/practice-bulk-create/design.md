# 練習の一括作成

最終更新: 2026-08-01

横断制約は [platform/design.md](../platform/design.md) を参照。タスクは [tasks.md](./tasks.md)。

## 1. 目的

管理画面で、選択中の演奏会に練習日程をまとめて追加できるようにする。1件ずつの登録負荷を減らす。

当初はサークルスクエアからの自動同期を検討したが、取得手段（公式 API なし・CSV 出力は実務上不可・iCal は会場マスタの住所を欠く）が要件を満たさないため、ポータル内の一括作成に切り替えた（[ADR-0024](../adr/0024-prefer-bulk-practice-create-over-circle-square-sync.md)）。

UI 改善（トグル表示・行複製・会場の即時追加）は [ADR-0026](../adr/0026-bulk-practice-toggle-duplicate-and-venue-modal.md) を参照。

## 2. スコープ

**やること**

- 選択中演奏会への練習の**新規追加のみ**を、複数行まとめて実行する
- 各行の会場は「未設定」または既存マスタから選択する
- 会場の新規登録は一括フォーム内の modal から**即時保存**し、保存後すぐ行のセレクトで選べる
- 管理者画面（`/admin/practices`）からのみ実行する
- 一括 UI はボタンで開閉し、普段は出さない（下書きは閉じても保持）
- 「行を追加」は空行、「この行を複製」でその行の内容をコピーした行を末尾に追加できる

**やらないこと**

- サークルスクエア／iCal／外部 CSV との自動連携
- 既存練習の一括更新・削除
- 一括送信時に会場を新規 INSERT すること（会場作成は単件 API／modal に分離）
- 会場マスタの一括更新・削除
- Cron / 定期実行

## 3. 同期・反映ポリシー

| 対象 | 動作 |
| --- | --- |
| 練習 | 入力行ごとに INSERT。既存行は触らない |
| 会場（既存選択） | 指定 ID を `venue_id` に設定。マスタは更新しない |
| 会場（新規） | 一括 mutation の対象外。modal から既存の会場作成処理で即 INSERT（同名再利用など会場側の既存ルールに従う） |
| ポータル固有列 | 対象外（録音・出欠 URL・資料・ボウイング・お知らせなど） |

## 4. 起動

- 管理者（`requireAdmin`）のみ
- `/admin/practices` の一括追加 UI からサーバ関数を1回呼び出す
- 専用の定期実行基盤は追加しない

## 5. 入力と上限

- 1回あたり最大 **30** 行（`MAX_BULK_PRACTICES`）。超過はエラー
- 1行以上必須
- 各行の項目は単件作成と同じ（日付必須、開始／終了任意、詳細任意）＋会場は `venueId`（任意）
- 終了時刻は開始より後（単件と同じ）
- 全部成功または全部失敗（検証を先に済ませ、D1 書き込みは件数に比例してクエリを増やさない）

## 6. 処理の骨格

1. 行数・各行・会場 ID を zod で検証する
2. 演奏会の存在を確認する
3. 指定された既存会場 ID の実在をまとめて確認する
4. 練習行をまとめて INSERT する
5. 追加した練習件数を返す

想定クエリはおおよそ「演奏会確認・会場確認・練習 INSERT」程度に収め、サブリクエスト上限（50）を超えない。

## 7. データモデル

追加テーブルや外部キー列は不要。既存の `venues` / `practices` を使う。定義は [archive/initial/design.md の6章](../archive/initial/design.md) を凍結参照。

## 8. 画面

- `/admin/practices` に「一括追加」トグルを置く。閉じているときは入力 UI を出さない
- 開いているときだけ行の追加・削除・複製、実行中・成功・失敗が分かる表示を出す
- 閉じていても下書きは保持する。演奏会切り替えでフォーム state を初期化する（`key` に演奏会 ID）
- 「行を追加」は空行。「この行を複製」はその行の日付・時刻・会場・詳細をコピーした新行を末尾に足す（上限内）
- 会場セレクトは単件と同じく「未設定」＋会場一覧。モード切替（未設定／既存／新規）は置かない
- 「会場を新規追加」で modal を開き、保存成功後に会場一覧を更新してセレクトから選べるようにする
- 単件の「練習を追加」フォームは現状維持
- extra ロールには出さない（管理画面内のみ）

## 9. 制約

- 無料プランのサブリクエスト上限を守る（行数分の N+1 INSERT にしない）
- 画面コンポーネントから `src/db/schema.ts` を直接参照しない
- 上限定数は `src/lib/limits.ts` に置く

## 10. 受け入れの目安

- 管理者が一括追加で複数練習を登録できる
- 一括 UI はボタンで開閉でき、閉じても下書きが残る（演奏会切替で消える）
- 「行を追加」は空、「この行を複製」でコピーできる
- 会場 modal で即保存でき、その後の一括入力で選べる
- 一括送信時に会場を新規作成しない
- 31行以上は拒否される
- extra は実行できない
- サークルスクエア連携や Cron を追加していない
