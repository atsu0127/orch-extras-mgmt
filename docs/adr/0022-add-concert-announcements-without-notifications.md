# 演奏会ごとのお知らせを最新順で表示し、通知と既読管理は持たない

## Context and Problem Statement

初回リリースのポータルは必要な情報を1か所で確認できる一方、内容が変わったときに再び開く動機が弱い。エキストラが練習前や日常に最新情報を確認でき、管理者が1件を1〜2分で更新できる仕組みを、個人アカウントや別の通知基盤を増やさずに追加したい。

## Considered Options

- 演奏会ごとのお知らせをホームに最新順で表示し、通知と既読管理は持たない
- 端末内に既読日時を保存し、未読バッジを表示する
- 団体全体のお知らせと演奏会ごとのお知らせを両方扱う
- メールや外部サービスにも通知する

## Decision Outcome

採用: **演奏会ごとのお知らせをホームに最新順で表示し、通知と既読管理は持たない**。

選択中の演奏会に情報を限定すると、利用者は今参加している演奏会の更新だけを確認できる。最新のお知らせをホームへ常時表示するため、個人アカウントや端末ごとの状態は不要である。団体共通のお知らせ、外部通知、予約投稿は管理項目と運用経路を増やすため、必要性が実運用で確認されるまで追加しない。

お知らせはタイトル、本文、任意の外部URLを持ち、1演奏会あたり最大10件とする。少数に限定することで専用の閲覧ページやページングを作らず、ホーム上で最新1件と過去分を確認できる構成にする。

### Consequences

- 良い: エキストラが選択中の演奏会の変更点をホームで確認できる
- 良い: 管理者は短い投稿だけで更新を伝えられ、別の通知サービスを管理しなくてよい
- 良い: 個人アカウント、個人データ、端末内状態を追加せずに済む
- 悪い: ポータルを開く前に新着を知らせることはできない
- 悪い: 既読・未読を区別できず、重要なお知らせの固定や予約投稿もできない
- 悪い: 10件を超える場合、管理者が古いお知らせを削除する必要がある
