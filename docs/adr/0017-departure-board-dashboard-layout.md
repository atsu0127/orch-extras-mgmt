# ダッシュボードは出発案内型で「次の練習」を最上位に置く

## Context and Problem Statement

Phase 6 で Mantine を導入したあと、閲覧ホームの見た目と情報配置が「薄いテンプレート」に見え、エキストラが開いた瞬間に欲しい情報へ届きにくかった。影響するのは設計書7.2、認証後レイアウト、ダッシュボード、共通ナビである。調査したチーム運営・旅程・イベント系アプリでは、直近予定を第一画面の主役にし、操作導線をその近くに置くパターンが優勢だった。

## Considered Options

- 出発案内型: 大きな日付＋時刻・会場・地図・カレンダーを次の練習にまとめ、本番と出欠をその直後に置く。主要画面は下部固定ナビ
- フォーカスパネル型: 次の練習を暗い面にまとめる
- アジェンダレール型: 縦レールで予定の流れを見せる
- 設計書どおり演奏会情報を最上段に残す

## Decision Outcome

採用: **出発案内型**。日付の認識が最速で、第一画面に次の練習・地図・カレンダー・本番・出欠が収まる。フォーカスパネル型はダーク基調の好みが分かれ、アジェンダレール型は横幅を食い、演奏会情報を最上段に置く案は利用者の優先度（次の練習 → 本番・出欠）と食い違う。

主要画面の移動は下部固定ナビ（ホーム / 練習日程 / 曲・ボウイング。管理者は管理を追加）とし、演奏会セレクタはヘッダに常時置く。

### Consequences

- 良い: 開いて数秒で次の練習の日時・会場・地図へ到達できる
- 良い: 出欠と本番情報が第一画面内に残り、スクロール依存が減る
- 悪い: 設計書7.2の旧順序（演奏会情報が最上段）を変えるため文書更新が必要
- 悪い: 下部ナビ分の余白が本文に必要になる
