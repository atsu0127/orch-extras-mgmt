# PC幅では上部アプリバー型シェルとし、コンテンツ幅を読書・管理向けに広げる

## Context and Problem Statement

Phase 6 でスマホ優先のシェル（下部ナビ、`max-width: 42rem`）を固めたが、PC幅ではヘッダが縦積みのまま・本文が細いスマホ柱のまま残り、管理サブナビが折り返して二段になるなど、デスクトップの慣習と乖離していた。ナビのアクティブ下線も `activeProps.style` 依存で切り替わらない不具合があった。影響するのは設計書7.2、認証後レイアウト、ホームのパンフレット配置、管理サブナビ、共通CSSである。

## Considered Options

- 左サイドバー型（Linear / Notion 風）に主ナビを移す
- 上部アプリバー型（GitHub / 会員ポータル風）にし、主ナビは横タブ、本文幅だけ広げる
- スマホ柱（42rem）を中央に残し、余白だけ広げる

## Decision Outcome

採用: **上部アプリバー型**。主画面は4項目程度なのでサイドバーは過大で、情報ポータルとしてはトップの横タブが一般的。スマホでは従来どおり下部ナビ（アイコン＋短いラベル）を維持する。

PC（`min-width: 48rem`）では次を満たす。

- ヘッダ帯は画面全幅。中身と本文は同じコンテンツ幅（約 `64rem`）で左右を揃える
- ヘッダ1行にブランド・主ナビ・演奏会セレクタ・ログアウトを置く
- 主ナビの選択表示は下部ナビと同じく `data-active` + CSS の下線とし、インライン style の残置を避ける
- ホームは次の練習｜本番＋出欠の2カラム（プログラム表の見開き）
- 管理サブナビは折り返さず1行のタブストリップ（不足時は横スクロール）。管理本文は約 `68rem`
- `/admin` は演奏会へ誘導し、管理トップの一覧メニューは置かない（主ナビ「管理」＋サブナビの二重導線を避ける）
- 主ナビのラベルは `white-space: nowrap` と縮まないグリッド列で、日本語の1文字折り返し（縦書きに見える状態）を防ぐ。狭い PC 幅ではナビを2行目に逃がす

スマホ柱のまま余白だけ広げる案はモニタを活かせず、サイドバーはナビ項目が少なく空白が目立つ。

### Consequences

- 良い: PCでも「今どこにいるか」が一目で分かり、管理操作の横幅が確保できる
- 良い: スマホの情報優先順（ADR-0017）と見た目言語（ADR-0018）を崩さない
- 悪い: ブレークポイントごとのヘッダ構造が分岐し、CSSとマークアップの対応を保つ必要がある
