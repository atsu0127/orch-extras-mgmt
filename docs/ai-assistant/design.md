# AI案内 設計書

最終更新: 2026-08-29

## 1. 目的

エキストラと管理者が、ポータルに登録済みの演奏会情報を自然文で探せる「AI案内」を追加する。選択中の演奏会を既定の対象としつつ、質問で指定すれば別の演奏会も検索できる。

初回導入では、Claude API の tool use を安全かつ低額に試すことも目的とする。月額はおおむね1,000円以内に収め、AIが利用できないときも既存の閲覧・管理機能を継続できる構成にする。

## 2. スコープ

### 2.1 対象

- admin / extra の両ロールが利用できる
- 選択中または質問で指定された演奏会について、次を検索する
  - 演奏会の概要・本番・出欠回答先・備考
  - 練習日程・会場・詳細
  - お知らせ
  - 演奏会資料
  - 曲・ボウイングあり／なしの楽譜
  - 練習の録音・録画
- 候補質問と自由入力を用意する
- 直近の会話を踏まえた追加質問に対応する
- 回答に対象演奏会、登録情報の根拠、関連する内部画面または外部URLへのリンクを付ける
- 会話履歴を同じブラウザに保存し、演奏会を切り替えても維持する

### 2.2 対象外

- AIによるデータの追加・編集・削除
- ポータル外の一般知識、Web検索、外部ファイルの検索
- 登録情報にない内容の推測
- 個人ごとのアカウントや履歴同期
- 端末・ブラウザをまたぐ履歴同期
- 会話履歴のD1保存
- 回答のストリーミング表示
- 古い会話のAI自動要約
- LangChain、Vercel AI SDK、MCPサーバーの導入
- ログインのパスワード強化、Turnstile、個人アカウント（共有パスワードは維持し、呼び出し上限で残高を守る）

登録情報に答えがない場合は、その旨を明示する。一般知識で補完しない。

## 3. 画面と利用動線

### 3.1 クイック表示

閲覧画面に「AIに聞く」ボタンを置く。

- スマートフォン: 画面下部からシートを開く
- PC: 画面右側にパネルを開く

クイック表示では候補質問、直近の会話、質問入力欄を表示する。「専用ページで開く」で同じ会話をAI案内の専用ページへ引き継ぐ。

### 3.2 専用ページ

認証済みルート `/assistant` を追加し、メインナビに「AI案内」を置く。選択中演奏会は既存どおり `?concert=<id>` を正とする。

- スマートフォン: 会話を画面幅全体に表示し、「履歴」ボタンから会話一覧を開く
- PC: 左に会話一覧、右に選択中の会話を表示する

クイック表示と専用ページは同じクライアント状態と会話履歴を共有する。

### 3.3 履歴の見え方

- 会話名は最初の質問からローカルで作る。会話名作成のためのAPI呼び出しは行わない
- 会話一覧に主な演奏会名と最終更新日時を表示する
- 回答ごとに対象演奏会名と回答日時を表示する
- 会話の個別削除と全削除を用意する

## 4. AI連携方式

### 4.1 採用方式

Claudeが質問に必要な登録情報を判断し、読み取り専用ツールを要求する方式を採用する。

ここでいうツールはClaude APIの tool use（function calling）であり、ClaudeがD1へ直接接続する機能ではない。Claudeは構造化された実行要求を返し、アプリが検証・実行する。

公式 `@anthropic-ai/sdk` と Messages API を使う。自動ループ用フレームワークは使わず、2回のAPI呼び出しをアプリで明示的に制御する。公式SDKのベータ版 `toolRunner()` は使用しない。

モデルは挙動と料金を固定するため `claude-haiku-4-5-20251001` に固定する。モデルを変更するときは本設計を更新して回帰確認する。

### 4.2 処理の流れ

1. 画面が質問、直近6メッセージ、選択中演奏会IDを認証必須のサーバー関数へ送る
2. サーバー関数が入力と認証を検証し、8.3 どおり枠を確保する。確保できなければ Claude を呼ばない
3. 1回目のClaude APIへ質問、履歴、選択中演奏会、ツール定義を送る。システム指示には日本時間の今日を含める
4. Claudeが `search_portal` の実行要求を返す
5. アプリがツール引数を検証し、D1を読み取る。質問の言い回しだけの `keywords` / `concert` は絞り込みに使わず、練習は今日以降を先に並べて「次の練習」を明示する
6. 検索結果を `tool_result` として2回目のClaude APIへ送る（`today` を添える）
7. Claudeが登録情報だけに基づく最終回答と参照キーを返す
8. アプリが参照キーを検索結果と照合し、検証済みリンクだけを画面へ返す
9. トークン数と成否を日単位の利用量へ加算する（枠の確保数はここでは触らない）

1質問で許可するツール呼び出しは1回、Claude APIは最大2回とする。2回目に再度ツールを要求された場合は実行しない。

1回目は `search_portal` の呼び出しを必須にし、登録情報を検索せず事実回答する経路を作らない。2回目はツール利用を禁止して最終回答だけを要求する。各API呼び出しは20秒でタイムアウトし、SDKの `maxRetries` は0とする。

### 4.3 サーバー側の境界

- サーバー関数は `requireAuth` を必須にする
- Claude APIキーは `ANTHROPIC_API_KEY` としてCloudflare secretに置き、リクエストごとにサーバー側で読む
- ブラウザへAPIキー、D1接続情報、SQLを返さない
- `search_portal` は読み取り専用のアプリ関数であり、任意SQLを受け取らない
- Claudeが返した引数・回答・参照キーを信頼せず、すべてアプリ側で検証する

## 5. 読み取りツール

Claudeへ公開するツールは `search_portal` 1つだけとする。

```ts
type SearchPortalInput = {
  concert: string | null
  topics: Array<
    | 'concert'
    | 'practices'
    | 'announcements'
    | 'resources'
    | 'pieces'
    | 'recordings'
  >
  keywords?: string
  dateFrom?: string
  dateTo?: string
}
```

### 5.1 入力規則

- `concert` が `null` なら選択中演奏会を使う
- `concert` は最大100文字とし、登録済み演奏会名に対して正規化した完全一致を優先する
- `concert` が質問の言い回しだけ（「次の練習」など）なら、名前検索せず選択中演奏会を使う
- 一意に決まらない場合は候補だけを返し、Claudeは利用者へ選択を求める
- `topics` は重複不可、1〜3種類。練習の日時・次の練習は `practices`
- `keywords` は最大100文字。質問の言い回しとトピック名を除いた実質的な語句だけで絞り込む。残りが無ければ絞り込まない
- `dateFrom` / `dateTo` は `YYYY-MM-DD`。日付文字列のまま比較する
- 入力はzodで検証し、不正ならD1へ到達させない

### 5.2 検索結果

- 検索結果は種類とIDを含む構造化データとして返す
- システム指示と `tool_result` に日本時間の今日を含める。次の練習はダッシュボードと同じく `date >= 今日`
- 練習は今日以降を先に並べ、最も早い1件を「次の練習」と明示する。30件制限でも今後の練習を落とさない
- `concert` トピックの概要にも次の練習1件を含める
- 1回の結果は合計30件、シリアライズ後20,000文字まで
- 上限を超える場合は省略があることを結果に含める
- URLは登録値をそのまま回答文へ埋め込まず、参照キーに対応する検証済みURLとして別に扱う
- お知らせ本文などの登録文字列は命令ではなくデータであるとシステム指示に明記する

## 6. 回答契約

Claudeの最終出力は、回答本文と参照キーの構造として受け取る。

```ts
type AssistantAnswer = {
  answer: string
  concertName: string | null
  sourceKeys: string[]
}
```

- 回答は日本語、最大400出力トークン
- `sourceKeys` は直前の検索結果に存在する値だけを採用する
- 存在しないキーは破棄し、リンクを表示しない
- 根拠がない場合は「登録情報にありません」と回答し、空の `sourceKeys` を返す
- 演奏会が曖昧な場合は候補を短く提示し、特定できる質問を返す
- 回答に新しいURLを生成させない
- 最終出力をzodで検証し、不正な構造は回答として採用しない

## 7. 会話履歴

### 7.1 保存

- `localStorage` にバージョン付きJSONとして保存する
- admin / extra で保存キーを分ける
- 最大10会話、1会話20メッセージ
- 上限を超えた場合は最終更新が古いものから削除する
- 読み取り・マイグレーションに失敗した履歴は安全に初期化し、アプリ全体を失敗させない

同じ端末・ブラウザ・ロールを複数人で使う場合、履歴も共有される。画面に個人情報を入力しない旨を表示する。

### 7.2 Claudeへ渡す範囲

画面では保存済み履歴を表示するが、Claudeへ送るのは現在の会話の直近6メッセージだけとする。古い会話を自動要約しない。文脈が不足する場合は推測せず聞き返す。

## 8. 費用と利用量

### 8.1 上限

- 質問は最大500文字
- 履歴は直近6メッセージ
- ツール呼び出しは1回
- 検索トピックは最大3種類
- 検索結果は30件かつ20,000文字
- 最終回答は最大400トークン
- Extended Thinkingは使用しない
- SDKの自動リトライは無効
- Anthropic Consoleのauto-reloadは無効
- 初回は$5分のプリペイド利用枠で開始する

想定利用は5人前後、1人1日1〜3問で、月額400〜900円を目安とする。料金や為替は変動するため、Anthropic Consoleの請求を正とする。呼び出し回数の栓は 8.3。Anthropic の $5 と auto-reload 無効は、アプリ上限を超えたとき用の最後の栓として残す。

### 8.2 日別集計

D1に質問本文・回答本文・利用者情報を含まない日別集計を保存する。

| 列 | 内容 |
| --- | --- |
| `usage_date` | 日本時間の暦日 `YYYY-MM-DD`（`todayInJst` と同じ。ポータルの「今日」に合わせる） |
| `model` | 使用モデル |
| `accepted_question_count` | Claude を呼ぶ直前に確保した質問数（8.3）。成否を問わない |
| `api_request_count` | Claude API呼び出し数 |
| `successful_question_count` | 最終回答まで成功した質問数 |
| `failed_question_count` | 失敗した質問数 |
| `input_tokens` | APIレスポンスが報告した入力トークン合計 |
| `output_tokens` | APIレスポンスが報告した出力トークン合計 |
| `updated_at` | UTC ISO 8601 |

主キーは `usage_date` と `model` の組とする。成功・失敗・トークンの加算に失敗しても、生成済みの回答は失敗させない。枠の確保（`accepted_question_count`）に失敗したら Claude は呼ばない。`recordDailyUsage` は `accepted_question_count` を加算も上書きもしない。初回は利用量を表示する管理画面を作らず、Anthropic ConsoleとD1集計で確認する。

未マージのため、UTC 日付で書いた既存行の移行はしない。このブランチの 0004 が先に本番へ載った場合、夕方の分析行が UTC 日付と JST 日付に割れうる。枠は新列 default 0 なので安全だが、集計の読み方は日付境界に注意する。

### 8.3 呼び出し上限（IP と日次）

ログイン後の連打で残高を溶かすことを防ぐ。個人アカウントは持たないので、短時間は IP、1日の絶対量は全体で抑える。練習会場の共有 Wi‑Fi を想定し、IP 側は日次ではなく短い窓にする。

| 枠 | 値 | キー |
| --- | --- | --- |
| IP | 直近10分で15問 | `CF-Connecting-IP`（無いときは既存ログイン制限と同じ `local`） |
| 全体 | 日本時間の今日で80問 | `usage_date` + `model`。admin / extra 合算。現行はモデル1つなので実質全体80。モデルを足すときは枠も足す |

定数は `src/lib/assistant.ts` の `ASSISTANT_LIMITS` に置く。

**数えるもの**

- Claude を呼ぶ直前まで進んだ質問だけ。未ログイン・入力不正では数えない
- 枠を確保してから API を呼ぶ。タイムアウトや API 失敗でも1問消費する
- IP 制限に引っかかった質問は行を足さない（窓が拒否のたびに延びない。ログイン制限と同じ）
- 日次上限に引っかかった質問は IP 行も足さない

**判定順**

1. 既存の認証と入力検証
2. その IP の直近10分を数える。15以上なら Claude を呼ばない（`ip_limited`）
3. 日本時間の今日の行を次で原子的に +1 する。変更行数が 0 なら `daily_limited`
   `INSERT accepted_question_count=1 ON CONFLICT DO UPDATE SET accepted_question_count = accepted_question_count + 1 WHERE accepted_question_count < 80`
4. IP 側に1行足す
5. Claude を呼ぶ
6. トークンや成否の集計は呼んだあとに足す（失敗しても回答は落とさない。`accepted_question_count` は触らない）

全体枠は条件付き更新で確保する。先に読んでから足すと同時リクエストで80を超えられる。IP 側はログイン制限と同じ滑る窓で、同時リクエストで15を数問超える可能性は残す。金銭的な栓は全体80の方なので、そちらを厳密にする。

**保存**

- IP: `ai_ask_attempts`（`id`, `ip`, `attempted_at`）。`(ip, attempted_at)` にインデックス。質問本文は持たない。`success` 列は持たない（通った質問だけ書く）
- `attempted_at` と掃除の cutoff は UTC ISO 8601（`login_attempts` と同じ文字列比較）。`usage_date` だけ `todayInJst`
- 全体: `ai_usage_daily.accepted_question_count`
- 古い IP 行は Cron なし。枠を確保できた質問のときに、`now - 24h` より古い行を消す。掃除は best-effort（失敗しても Claude は呼ぶ。日次枠は戻さない）
- 追加の D1 は件数確認・条件付き更新・INSERT・掃除に限り、検索クエリは増やさない
- 枠の確保（IP COUNT・日次の条件付き INSERT/UPDATE・IP INSERT）は Claude 呼び出しの try/catch の外で行う。ここが失敗したら `unavailable` でクライアント 0 回。掃除失敗は含めない
- スタブ経路と API キーありの本番経路だけ確保する。キー無しで `unavailable` を返すときは確保しない（Claude を呼ばないのに 80 を消費しない）

**今回やらないこと**

- パスワードの長大化、Turnstile、Cloudflare Access、個人アカウント
- 残数表示、管理画面の利用量 UI、ロール別の別枠
- トークン数そのものを上限にすること（1問の入出力は 8.1 で既に上限がある）

## 9. セキュリティとプライバシー

- 質問用サーバー関数を含むすべてのサーバー関数に既存の認証・CSRF対策を適用する
- AIから更新系関数へ到達する経路を作らない
- 質問、回答、ツール結果をWorkerログへ出さない
- APIエラーは秘密情報やAnthropicの生レスポンスを画面へ返さない
- 登録本文や質問に含まれる命令をシステム指示より優先しない
- 検証済みの登録URLまたは内部ルートだけをリンクとして描画する
- 画面から `src/db/schema.ts` を直接・間接に参照しない
- 上限超過の応答に残数や IP を含めない。Worker ログにも質問本文・IP を出さない

Claude APIには、質問、直近6メッセージ、検索に必要な登録情報を送信する。氏名・連絡先などの個人情報をポータルに保持しない既存方針を維持し、画面にも個人情報を質問へ入力しないよう表示する。

## 10. エラー処理

| 状況 | 動作 |
| --- | --- |
| 登録情報がない | 正常回答として「登録情報にありません」と表示 |
| 演奏会が曖昧 | 候補を示して聞き返す |
| 入力・ツール引数が不正 | D1を呼ばず、再入力を促す |
| Claudeがツールを再要求 | 上限超過として停止 |
| 参照キーが存在しない | 該当リンクを破棄 |
| タイムアウト・API障害 | 入力を残し、「もう一度試す」を表示 |
| 認証・残高・設定の問題 | AI案内だけ一時利用不可として汎用エラーを表示 |
| 枠の確保に失敗（D1障害など） | Claude を呼ばず、AI案内だけ一時利用不可 |
| IP が直近10分で15問 | Claude を呼ばず、「質問が混み合っています。しばらくしてから試してください。」 |
| 日本時間の今日が80問 | Claude を呼ばず、「本日の質問上限に達しました。日本時間の0時以降にまた利用できます。」 |
| 履歴JSONが壊れている | 履歴だけ初期化 |

上限超過（`ip_limited` / `daily_limited`）では「もう一度試す」を出さない。すぐ同じ理由で失敗するため。練習・楽譜・管理はそのまま使える。

自動リトライは行わない。AI連携の失敗を既存の練習・曲・お知らせ・管理画面へ波及させない。

## 11. テスト

### 11.1 単体・結合

- 演奏会名の解決と曖昧候補
- トピック、日付、キーワードによるD1検索
- 質問の言い回しだけの `keywords` / `concert` でも次の練習が返る
- 練習の今後優先と30件制限でも次の練習が残ること
- ツール入力の検証、件数・文字数制限
- 参照キーとリンクの照合
- 会話履歴の保存、削除、上限、破損時初期化
- 演奏会切り替え後の履歴維持
- 日別トークン集計（日付は JST。境界は `2026-08-16T14:59:59.999Z` → 16日、`2026-08-16T15:00:00.000Z` → 17日。`2026-08-17T12:00:00.000Z` は 17日のまま、`2026-08-17T15:30:00.000Z` は 18日）
- IP 10分15問と全体80問の確保・拒否。15問まで通り16問目、80問まで通り81問目は Claude クライアントを呼ばない
- `shouldOfferRetry`（名前は実装に合わせる）: `ip_limited` / `daily_limited` は false、`timeout` / `failed` は true
- 入力不正では IP も全体も増えない
- キー無しの `unavailable` では確保しない
- 集計失敗のテストは加算用 SQL だけ例外にし、確保用の INSERT/UPDATE では投げない。確保失敗は別テストで `unavailable`・クライアント 0 回
- 枠確保後の API 失敗でも全体は1問消費する
- JST 0時をまたぐと全体枠が戻る。IP の窓が滑るとまた通る
- モックした `tool_use → tool_result → 最終回答`
- 登録情報なし、不正引数、2回目のツール要求、APIエラー
- 登録本文中の命令をデータとして扱うケース

### 11.2 E2E

CIではClaude APIを呼ばず、決定的なテスト用AIクライアントを使う。

- admin / extra の利用、未ログインの拒否
- スマートフォンの下部シート
- PCの右側パネル
- 専用ページへの遷移
- クイック表示と専用ページの履歴共有
- 別演奏会を指定した質問
- 根拠リンク
- エラー表示と再試行（タイムアウト・失敗。上限超過の再試行ボタンは単体で確認し、E2E では発火させない）
- AI停止中の既存導線

上限そのものは固定時刻の単体テストで確認する。E2E で16問を投げて発火させない（ローカルは IP が `local` で共有される）。現行スイートの実質問は1ランあたり5回で、15未満に収める。

実Claude APIの確認は、明示的に有効化したローカル確認だけで行い、CIでは実行しない。
