# サークルスクエア同期

最終更新: 2026-08-01

横断制約は [platform/design.md](../platform/design.md) を参照。タスクは [tasks.md](./tasks.md)。

## 1. 目的

サークルスクエア上の会場・日程情報を正の入力源とし、管理者がボタン操作でこのポータルの会場マスタと演奏会／練習へ反映できるようにする。手動の二重入力を減らす。

## 2. スコープ

**やること**

- 会場: 同期対象に含まれ、ポータルにまだ無いものだけ**追加**する（既存の更新・削除はしない）
- 演奏会・練習: 名前・本番日・会場紐付け・日付・開始／終了時刻・**詳細**をサークルスクエア側を正として**上書き**する
- 管理者画面の同期ボタンから明示実行する
- 取得手段は未確定のため、実装前に調査してこの設計書を更新する

**やらないこと**

- Cron / 定期自動同期
- メンバー名簿など個人情報の同期
- 出欠の集計結果の取り込み
- 出欠 URL、演奏会資料、録音・録画、曲・ボウイング、お知らせなどポータル固有項目の上書き
- サークルスクエアに無い会場・日程の自動削除（カスケード削除は既定にしない。必要なら調査後に別途合意）

## 3. 同期ポリシー

| 対象 | 動作 |
| --- | --- |
| 会場 | 未登録なら INSERT のみ。既存は名前が一致しても更新しない |
| 演奏会 | 対応キーで特定し、同期対象列だけ UPDATE。無ければ INSERT |
| 練習 | 同上。`detail`（詳細）も同期対象 |
| ポータル固有列 | 触らない（出欠 URL／補足、資料、録音、ボウイング、お知らせ、認証・設定） |

「同一会場」「同一演奏会／練習」の判定キー（名前完全一致、外部 ID など）は取得手段の調査（T1）で決め、本節とデータモデル節を更新する。

## 4. 起動

- 管理者（`requireAdmin`）のみ
- 管理画面の同期ボタンからサーバ関数を1回呼び出す
- 専用の定期実行基盤は追加しない（platform の方針を維持）

## 5. 取得手段（未確定）

T1 で次を比較し、採用を1つに決めてこの章を書き換える。必要なら ADR を1本追加する。

1. 公式 API / エクスポート API（資格情報は Workers secret）
2. 管理者がダウンロードした CSV 等のアップロード取り込み（スクエアへの自動ログインなし）
3. その他（画面スクレイプ等）— 利用規約・脆さ・秘密情報の観点で原則非推奨

調査成果物:

- 採用手段とその理由（不採用の簡潔な理由付き）
- 認証・秘密情報の置き方
- サークルスクエア項目 → ポータル列の対応表（会場／演奏会／練習／詳細）
- 想定件数と、無料枠のサブリクエスト／CPU への当てはめ

## 6. 同期処理の骨格

取得手段が決まってから実装する。

1. 外部データを正規化する（会場 / 演奏会 / 練習）
2. 会場: 未登録のみ追加
3. 演奏会・練習: 対応キーで upsert（同期対象列と詳細のみ）
4. 結果（追加・更新件数、スキップ、失敗理由）を画面へ返す
5. 秘密情報・個人情報をログやレスポンスに出さない

## 7. データモデル（予定）

T1 の結論に応じて外部キー列や同期メタデータ（最終同期時刻など）を足す可能性がある。変更内容はこの節と [platform/design.md](../platform/design.md) の「データモデルの所在」から辿れるようにする。現行の `venues` / `concerts` / `practices` 定義は [archive/initial/design.md の6章](../archive/initial/design.md) を参照。

## 8. 画面

- 管理画面に同期の実行導線を置く（具体パスは実装時に既存管理 IA へ合わせる）
- 実行中・成功・失敗が分かる表示にする
- extra ロールには出さない

## 9. 制約

- 無料プランのサブリクエスト上限（D1 と外部 fetch を含む）を超えない。件数上限や分割が必要なら T1 で決める
- 資格情報が要る場合は D1 に生パスワードを置かない
- 画面コンポーネントから `src/db/schema.ts` を直接参照しない（AGENTS.md の規約）

## 10. 受け入れの目安

- 管理者がボタンで同期を実行できる
- 未登録会場だけが追加され、既存会場は変わらない
- 演奏会／練習の同期対象列と詳細が反映され、ポータル固有列は残る
- extra は実行できない
- 取得手段・対応表がこの design に追記済みである
