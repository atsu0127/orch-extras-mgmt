# サークルスクエア同期 — タスク

設計は [design.md](./design.md)。横断制約は [platform/design.md](../platform/design.md)。サイズは相対見積り（S: 1時間以内 / M: 半日 / L: 1日以上）。

## 進捗

- **設計着手**（2026-08-01）— 文書構成の再編に合わせ、同期機能の design / tasks を作成。取得手段は未確定
- 次に着手できるもの: **T1**（取得手段の調査）

## 進め方

```text
T1（取得手段の調査）─┬→ T2（データモデル・正規化）─┐
                    └→ T3（取得アダプタ）──────────┴→ T4（同期サーバ関数）→ T5（管理UI）→ T6（E2E・文書）
```

T1 の結論で T3 の中身と、T2 以降の見積りを見直してよい。実装は調査完了後の別 PR を原則とする。

## タスク

| ID | 内容 | 完了条件 | 依存 | サイズ |
| --- | --- | --- | --- | --- |
| T1 | サークルスクエアからの取得手段を調査する（API / CSV アップロード / その他） | 採用手段・不採用理由・認証・項目対応表・件数見積りを [design.md](./design.md) に追記。必要なら ADR を追加し platform の索引へ1行 | — | M |
| T2 | 同期用のデータモデル（外部キー等）と正規化・反映ロジック | 単体テストで「会場は未登録のみ追加」「演奏会／練習は対象列と詳細を上書き」「ポータル固有列は保持」が通る | T1 | M |
| T3 | T1 で決めた取得アダプタ | フィクスチャまたはモックから正規化結果まで単体テストが通る | T1 | M |
| T4 | 同期サーバ関数（admin・ボタン用） | 件数・エラーを返し、`requireAdmin` とサブリクエスト上限を守る。秘密情報をログに出さない | T2, T3 | M |
| T5 | 管理画面の同期ボタン UI | 実行・結果表示・失敗メッセージ。extra には出ない | T4 | S |
| T6 | E2E、README、進捗更新 | 管理者だけ同期でき、全検査（lint / typecheck / test）が通る | T5 | M |

## 受け入れ条件

- [ ] T1 により取得手段が design に明記されている
- [ ] 管理者が同期ボタンで実行できる
- [ ] 未登録の会場だけが追加され、既存会場は更新・削除されない
- [ ] 演奏会／練習の同期対象列と詳細が反映される
- [ ] 出欠 URL・資料・録音・ボウイング・お知らせは同期で変わらない
- [ ] extra は同期を実行できない
- [ ] Cron や定期実行基盤を追加していない

## 実装時の注意

- 会場: 追加のみ。既存の更新・削除はしない
- 演奏会／練習: 同期対象列と詳細は上書き、ポータル固有列は維持
- サークルスクエアに無い行の自動削除は、別途合意があるまで入れない
- 画面から drizzle スキーマを直接 import しない
