# フェーズタスクの実施

コマンド名の後にユーザーが指定したタスク ID（例: `T1-1`、`T1-1〜T1-3`）を実施する。
指定が無ければ `docs/tasks.md` の進捗セクションを読み、次に着手できるタスクを提案して確認を取る。

進め方・規約・環境上の注意は `AGENTS.md` に従う。ここではタスク実施に固有の点だけを補う。

## 着手前に確認すること

1. `docs/tasks.md` で対象タスクの**内容・完了条件・依存**を確認する。依存タスクが未完了なら、着手できるかを先に確認する
2. `docs/design.md` の該当章を読む。どの章が対応するかはタスクの内容から判断する（データモデルは6章、認証は8章、リンク切れ検知は9章、CI/CD は12章）
3. アカウント側の作業（`docs/tasks.md` の A-1〜A-6）が前提になっていないか確認する。必要なら先に依頼する

## 完了の基準

`docs/tasks.md` に書かれた完了条件を満たしたことを、**実際に動かして確認する**。確認方法が設計書の記述と噛み合わない場合は、代替手段を提示して合意を取り、合意した内容で `docs/tasks.md` の完了条件を更新する。

## PR に含めること

- 実施したタスクの一覧
- 設計上の判断とその理由（特に設計書に書かれていないことを決めた場合）
- 確認したことと、その確認方法
- マージ前に必要な作業（GitHub Secrets の登録など、コード以外で必要なもの）
